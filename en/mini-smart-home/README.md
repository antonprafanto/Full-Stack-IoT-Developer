# 🏠 Mini Smart Home project — reference version

🌐 **English** · [Bahasa Indonesia](../../proyek-rumah-pintar-mini/README.md)

This folder holds the curriculum's **running-project code** in its latest version. Every module adds one or two parts; the `code/` folder of each module keeps a "snapshot" of that week, while this folder always holds the newest version.

> **For learners:** your own project lives in your own repository, `mini-smart-home`, which you create with GitHub Desktop in [Module 3](../phase-0-foundations/module-03-cpp-for-esp32/README.md#-add-on-to-mini-smart-home). This folder is the **answer key and reference**. The v0.1.0 skeleton (Module 3), the `tools/` folder (Module 4), and `PIN-MAP.md` (Module 5) are meant to be copied as they are. From Module 5 on, you write the firmware yourself with the guidance in each module — compare it with yours if you get stuck, but don't copy it blindly.

All actuators have been connected to the canonical pins since v0.2.0: lamp and fan relays, the pump through a MOSFET, the curtain servo, a buzzer, and a manual button. Since v0.3.0, all five sensors are read for real (DHT22, LDR, capacitive soil sensor, PIR, HC-SR04), and there are two local automation rules: automatic watering (the pump refuses to run when the water tank is too low) and the automatic lamp (dark + motion). Since v0.4.0, an OLED display shows every reading, and readings can be logged to a microSD card (optional; with a regulated module, press **EN** after turning on the MB102); Node 1 keeps running even without the display or the card. Since v1.0.0, `loop()` never waits (the `millis()` pattern and *state machines*), the program consists of 24 files (`node-1-home.ino`, `config.h`, and eleven `.h`/`.cpp` modules), a watchdog restarts a stuck program, the watering threshold and the boot counter are stored in NVS, logging is leveled DEBUG/INFO/ERROR, and a long press of the button opens a status page (uptime, reason for the last restart, boot number, threshold, version, free memory). Since v1.1.0, Node 1 connects to your home Wi-Fi through the WiFiManager portal (the password is not written in the code; hold the button while pressing EN to open the portal), reconnects by itself when the Wi-Fi drops, gets the time from the internet (NTP), sends its six readings as data-contract JSON to `tools/webhook-receiver.js` every minute, and its lamp can be turned on or off from a phone browser (`http://node1.local/` or its IP address); the program now has 26 files and is uploaded with the ESP32 Dev Module board option (Partition Scheme Minimal SPIFFS, Flash Mode DIO). Since v1.2.0, all of its communication goes over MQTT following the [data contract](DATA-CONTRACT.md): `telemetry` every 10 seconds and immediately when something important happens, `vitals` every 5 minutes, an automatic online/offline status (*Last Will*), and lamp, fan, pump, and curtain commands that are always answered with an `ack`; the `/on` `/off` web server, `node1.local`, and HTTP sending are retired, and the status page shows `WiFi ok, MQTT ok`. Since v1.2.1, its broker is the Raspberry Pi gateway (`BROKER_ADDRESS`), so Node 1 stays connected even when the laptop is off. Since v1.3.0, Node 1 is also Node 2's bridge: it listens for ESP-NOW packets from Node 2 (`bridge.cpp`, with the 33-byte packet form in `node2-packet.h`), then publishes them to `msh/<device_id Node 2>/telemetry` and `/status` following data contract 1.1, with a `ts` from the time the packet arrived; up to 96 readings are held on the holding shelf while the broker can't be reached. Its radio no longer sleeps (`WiFi.setSleep(false)`) and doesn't reconnect by itself: only the 60-second guard tries again, and then the radio goes back to the router's channel so that Node 2 is still heard while the router is off. ESP-NOW encryption is on if there's a `keys.h` (its example is `keys.example.h`; `keys.h` itself is guarded by `.gitignore`). Since v1.4.0, Node 1 can read an RS-485 soil sensor over Modbus RTU (`rs485.cpp`, a MAX485 module on RX2/TX2 with DE/RE on D4; the status LED moves to D2): every 10 seconds it asks server 1 and adds `soil_rs485`, `soil_temperature`, and `ec` to `telemetry` (data contract 1.2), holding `null` if the sensor doesn't answer; after three times in a row without an answer, it asks every 60 seconds. This reading is off until it's switched on with the `rs485 on` command, and the choice is saved in NVS. You can try it from the Serial Monitor (`lamp on`, `fan off`, `pump 3`, `curtain 90`, `beep`, `status`, `info`, `threshold 35`, `log debug`, `wifi`, `wifi forget`, `send`, `node2`, `node2 reset`, `rs485`, `rs485 on`, `rs485 off`, `restart`), and it prints the reason for the last restart when it starts. Needs the ESP32Servo 3.2.1 library, DHT sensor library 1.4.7 (installed with it: Adafruit Unified Sensor 1.1.15), Adafruit SSD1306 2.5.17 (installed with it: Adafruit GFX Library 1.12.6 and Adafruit BusIO 1.17.4), WiFiManager 2.0.17, ArduinoJson 7.4.3, PubSubClient3 3.3.2, and ModbusMaster 2.0.1. |
