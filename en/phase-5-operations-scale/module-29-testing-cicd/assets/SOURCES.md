# Sources & Image Credits — Module 29

A recap of all the images in this folder. The original curriculum diagrams are licensed **CC BY 4.0**, and their `.svg` files are included so they can be edited. The diagrams follow the code of this module (`.github/workflows/ci.yml` with the six jobs `verify`, `test`, `build`, `staging`, `tag-release`, `deploy-vps`; `scripts/deploy.sh`, `scripts/smoke-test.sh`, `scripts/check-version.mjs`; `scripts/systemd/smarthome-update.service` and `.timer`; backend 2.0.0: `src/app.ts`, `src/integration/` with 20 integration tests, `src/config/server-version.ts`, `src/routes/health.ts`, `Dockerfile`; dashboard 2.0.0: three Vitest test files and `Dockerfile`; `compose.cloud.yml`, `CHANGELOG.md`, `.github/pull_request_template.md`, the root README and `edge/README.md`), the official documents the author read (GitHub Docs: Actions, the Container registry, branch protection; Docker Docs: multi-platform builds; `systemd.timer`; OpenSSH `sshd` and `ssh_config`; SemVer 2.0.0; Keep a Changelog 1.1.0), and the behavior the author tested on a **Raspberry Pi 5 running Ubuntu 26.04 (arm64)**: Docker Engine 29.1.3 with Docker Compose 2.40.3 and buildx 0.30.1, Node.js 24.21.0 on the "laptop" and `node:24.22.1-alpine3.24` in the job containers, TimescaleDB 2.30.2, Mosquitto 2.1.2, Chrome 156. **The author has no GitHub account, GHCR package, VPS, GitHub-hosted machine (runner), or second Pi.** The **English edition's lab** (6 November 2026) therefore ran every `run:` step of this module's `ci.yml` unchanged, except the two steps of `deploy-vps` (for that job it only evaluated the `if:`, and `scripts/deploy.sh` ran directly on the "VPS" as the key's `command=` runs it), with the author's **simulated runner** (the `uses:` steps simulated), with a local `registry:3.1.2` standing in for GHCR, and with the "VPS" and the "Pi" as **Compose projects on the same machine's Docker**, deployed by `scripts/deploy.sh` itself (HTTP local, no domain); the robot key's SSH restriction was tested with real OpenSSH in throw-away Alpine containers, and the alarm clock's round (the unit's `ExecStart`) was run by hand, without systemd; no privileged container and no forge were used. The story numbers in the diagrams come from the **Indonesian edition's final lab** of 4 November 2026 on the same machine and the same code: `ci.yml` as it is on a local **Gitea 28.2.0** forge with **Gitea Runner 5.2.4** and Docker-in-Docker containers (permitted by the user for that lab only, then deleted), real SSH into a simulated VPS container, the alarm clock imitated by a simulated scheduler, and the unit files only checked with `systemd-analyze verify` (systemd 259), not run by a real systemd. Lab numbers in the diagrams are marked "the author's lab" (the Indonesian edition's lab); the real GitHub times, how long the job `staging` pulls its images on GitHub (±1.1 GB), the timer's schedule after a reboot, and an amd64 image actually running are **not measured** and are never written as results. The GitHub screen in `branch-rule-merge-box` is a **reconstruction** from GitHub's documentation, not a screenshot. The addresses `203.0.113.10` (VPS) and `iot.yourname.my.id`, the users `house` (VPS) and `budi` (Pi), and the example branches `try/red` and `fix/login-text` are examples, in the style of Modules 27–28. The module's place in the plan: [Syllabus, Module 29](../../../SYLLABUS.md#module-29--testing--cicd-every-change-tested-and-deployed-automatically).

The screenshots come from the author's **English image lab** of 6 November 2026 (05:03–05:11 WIB), on the same **Raspberry Pi 5 with Ubuntu 26.04 (arm64)**, with **headless Google Chrome 156 (`Chrome/156.0.8078.47`)** driven over the DevTools protocol: `--lang=en-US`, the time zone emulated as `Asia/Jakarta`, 1280 × 800 CSS px at scale 2 as the laptop, and 375 × 812 at scale 2 with touch = **Chrome's device mode on the same machine, not a real phone** (dark mode for the phone shots). The code = this module's English code as it is, released through the English edition's lab: backend + dashboard **2.0.0**, then **2.0.1** (the small pull request of Practice 12), Caddy 2.11.7, Mosquitto 2.1.2, TimescaleDB 2.30.2, from `compose.cloud.yml` and `edge/compose.edge.yml`. The images are the ones the **simulated robot** built and pushed to the local registry in the English lab's runs; for the screenshots, the author used a **throw-away copy of that lab** (copies of its data, the same images, its Git history), where the "VPS" switched from 1.5.0 to 2.0.0 with `sh scripts/deploy.sh` (Practice 10.1) and then to 2.0.1 with the same script run as the robot key's forced command runs it (Practice 12.4), while the free-path "Pi" deployed 2.0.0 and then 2.0.1 with `DEPLOY_PARTS="center gateway" sh scripts/deploy.sh` run by hand (Practice 12.5); the copy was deleted afterwards. The "VPS" dashboard was opened at `http://127.0.0.1:6590` (**HTTP local, no domain and no HTTPS**; the text writes `https://iot.yourname.my.id`; the lab address shows on the `/api/docs` page, and the composite subtitles write both; the PWA service worker works there because Chrome treats 127.0.0.1 as a secure origin); the free-path dashboard was opened through the lab's Docker network, a stand-in for the Cloudflare Tunnel, where the PWA was allowed for the lab address only through a Chrome setting in the lab profile (`--unsafely-treat-insecure-origin-as-secure`; the reader's dashboard is HTTPS). The stopwatch line in `version-in-production` is the English lab's own run of the same release (merge → the simulated robot's push run → the tag → the forced command on the simulated VPS), not a GitHub time. **Headless Chrome only captures the page content: the address bar, terminals, phones, and GitHub screens never show** (and are not imitated). The devices on the screens are the **simulator** `tools/device-simulator.js` (the simulated Node 1 `f00d00000001` "Practice living room" and, on the free path, `f00d00000044`; signal, RAM, and uptime are simulator values); the accounts, devices, history, and the firmware release 1.7.1 come from the English Module 28 lab (1.7.1 = the author's compiled English firmware file, uploaded and checked there, never run on a board). The account in the shots is the lab example account `admin@home.test` (seen only as `Home Admin (admin)`; the Email field of the Login screen shows the placeholder `viewer@home.test`, the Password field is empty); no token, key, password, or cookie is in any image. The numbers and times are examples from the author's lab (6 Nov 2026, WIB), **not GitHub numbers** (an x64 runner, an amd64 VPS). The two optional Indonesian screenshots of the local forge are not part of this edition: its lab had no forge. All sources were accessed October–November 2026.
