# 🏠 Mini Smart Home project — reference version

🌐 **English** · [Bahasa Indonesia](../../../../fase-5-operasi-skala/modul-26-docker-compose/kode/README.md)

This folder holds the curriculum's **running-project code** in its latest version. Every module adds one or two parts; the `code/` folder of each module keeps a "snapshot" of that week, while this folder always holds the newest version.

> **For learners:** your own project lives in your own repository, `mini-smart-home`, which you create with GitHub Desktop in [Module 3](../../../phase-0-foundations/module-03-cpp-for-esp32/README.md#-add-on-to-mini-smart-home). This folder is the **answer key and reference**. The v0.1.0 skeleton (Module 3), the `tools/` folder (Module 4), and `PIN-MAP.md` (Module 5) are meant to be copied as they are. From Module 5 on, you write the firmware (and from Module 16 on, the backend) yourself with the guidance in each module — compare it with yours if you get stuck, but don't copy it blindly.

## How to run the whole system with one command (Module 26)

Since Module 26, every central service starts together from the project root on a laptop that only has Git and Docker (Docker Desktop on Windows and macOS, Docker Engine on Linux): no Node.js and no `npm install`. The full steps, including moving the Module 17–25 database and Grafana without losing data, are in [Module 26](../README.md).

1. Clone your repository, then open a terminal in its folder (the project root, where `compose.cloud.yml` is).
2. Copy `.env.example` to `.env`, fill in its five secrets with random text (the command that makes it is written in the header of `.env.example`) and `IMAGE_REGISTRY`. On Linux, macOS, and the Pi: `chmod 600 .env`.
3. New laptop only (the Module 17 and 25 cupboards don't exist yet): `docker volume create smarthome-data` and `docker volume create smarthome-grafana-data`. A laptop that still runs the old `smarthome-db` and `smarthome-grafana` containers follows the order of the move in Module 26 Practice 4 first: the old containers are stopped and removed before Compose starts, their cupboards stay.
4. `docker compose up -d --wait`. The first time, Compose pulls the images from the image shop, or builds the backend and dashboard images itself when the shop doesn't have them yet (a few minutes). Does this laptop have a different processor type from the laptop that built the images in the shop (Intel or AMD = `amd64`, an Apple silicon Mac or a Pi = `arm64`)? Add `--build` (`docker compose up -d --wait --build`): an image in the shop only fits the processor of its maker, so Compose builds it itself (slower, needs npm downloads). This command only finishes after every service is ready: long-running services show `Healthy`, one-off services `Exited`. Check with `docker compose ps -a` (one-off: `Exited (0)`).
5. New laptop: make the first admin account with `docker compose exec backend node src/db/manage-users.ts add admin@home.test "Home Admin" admin` (the password is asked twice). The dashboard is at **`http://localhost`**, Grafana at **`http://localhost:3000`**.

| Command (from the project root) | What it does |
| :--- | :--- |
| `docker compose ps -a` | the state of every service, including one-off services that are done (`Exited (0)`); without `-a` those services don't show |
| `docker compose logs -f backend` | the log of one service (also `mosquitto`, `grafana`, `web`, …); **Ctrl + C** only stops reading |
| `docker compose down` then `docker compose up -d` | stops and starts the whole home again; the history stays (prove it with [`scripts/fingerprint.sql`](scripts/fingerprint.sql)) |
| `docker compose stop mosquitto`, then `docker compose start mosquitto` | the central broker listens on every interface of the laptop and starts every time Docker starts: stop it before the laptop joins a public Wi-Fi (a café, a campus), start it again at home |

**Never** `docker compose down -v` (it deletes the cupboard of the broker password file), and never `docker volume rm` or `prune` for the `smarthome-data` and `smarthome-grafana-data` cupboards: without a backup, your history is gone. `.env` and the output of `docker compose config` hold every secret: don't paste them into a forum, an issue, or an AI. The details of each service are in `backend/README.md`, `frontend/README.md`, `grafana/README.md`, and `edge/README.md`.
