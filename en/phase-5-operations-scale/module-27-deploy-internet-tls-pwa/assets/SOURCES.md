# Sources & Image Credits — Module 27

A recap of all the images in this folder. The original curriculum diagrams are licensed **CC BY 4.0**, and their `.svg` files are included so they can be edited. The diagrams follow the code of this module (`compose.cloud.yml`, `.env.example`, `frontend/caddy/Caddyfile`, `frontend/vite.config.ts`, `edge/center-internet.conf`, `edge/gateway.conf`, `edge/bridge.example.conf`, `edge/acl-broker`, `edge/compose.edge.yml`, `edge/.env.example`, `scripts/copy-certificate.sh`, `scripts/renew-mqtt-certificate.sh`, `scripts/check-late-arrivals.sql`; backend 1.4: `src/config/env.ts`, `src/services/mqtt.ts`, `src/services/commands.ts`; frontend 1.3: `vite.config.ts`, `public/`, `README.md`; `DATA-CONTRACT.md`) and the behavior the author tested on a **Raspberry Pi 5 running Ubuntu 26.04 (arm64) playing the laptop, the VPS, the Pi, and the internet at once**, like the Indonesian edition: Docker Engine 29.1.3 with Docker Compose 2.40.3, Caddy 2.11.7, Mosquitto 2.1.2, TimescaleDB 2.30.2, Grafana 13.2.4, Node.js 24.22.1, Chrome 156. **The author has no VPS, domain, Cloudflare account, phone, mobile network, ESP32 with TLS, or router that can be unplugged.** Everything is simulated on that machine: the "internet" = a Docker network, Let's Encrypt = **Pebble 2.10.1** (a stand-in ACME CA that Let's Encrypt makes for testing), the DNS = **pebble-challtestsrv 2.10.1** (a stand-in for Cloudflare's DNS), the lab domain names = `iot.example.test` and `mqtt.example.test` (the diagrams write the reader's names `iot.yourname.my.id` and `mqtt.yourname.my.id`; the composite subtitles write both), "unplugging the home internet" = taking the gateway broker container off that network (`docker network disconnect`), and the phone = headless Chrome 412 px wide (tests) or device mode 375 px (screenshots). The numbers in the diagrams are **simulated-lab** numbers on this module's code, the same story numbers as the Indonesian edition: the 10-minute unplug timeline, the rise of the bridge queue, and the `check-late-arrivals.sql` result from the author's re-test on the final code (30 Oct 2026); the certificate issue time and the three `trustProxy` visitors from the code lab of 29 Oct 2026; the PWA shell size from the English build (`precache 10 entries (1054.22 KiB)`). None of them is a Let's Encrypt, VPS, or real home-network number; a real router and a real mobile network can make the "blind window" shorter or longer. The "original Syllabus wording" comparison in the bridge diagram comes from the author's re-test on the final code with the Syllabus settings put in temporarily (the power-cut row: the author's research test in the same simulated lab). The Let's Encrypt certificate chain is drawn from Let's Encrypt's documents and was checked by the author with `openssl s_client` against a Let's Encrypt site (`api.open-meteo.com`, 29 Oct 2026); Pebble does not imitate that chain, so the bridge and the ESP32 against the real Let's Encrypt chain are **not tested**. The ufw, SSH, registrar, Cloudflare, and phone-install steps follow their official documents and were **not tested** by the author. The VPS IP `203.0.113.10` is an **example** address (a documentation block), and the laptop IP `192.168.1.10` and the Pi IP `192.168.1.37` are the same examples as earlier modules.

The screenshots come from the author's **English lab** of 30 October 2026 (17:45–18:50 WIB), on the same **Raspberry Pi 5 with Ubuntu 26.04 (arm64)**, with **headless Google Chrome 156 (`Chrome/156.0.8078.47`)** driven over the DevTools protocol: `--lang=en-US` (the Quick Win warning pages are Chrome's own English pages), the time zone emulated as `Asia/Jakarta`, 1280 px wide as the laptop, and 375 px = **Chrome device mode on the same machine, not a real phone and not a mobile network**; on this module's English code as it is: backend 1.4.0, dashboard 1.3.0 (PWA), Caddy 2.11.7, Mosquitto 2.1.2, TimescaleDB 2.30.2, Grafana OSS 13.2.4 (`/api/health`: version 13.2.4, commit `0e79aef9d91abf3bdadae9af15763029072fb45b`; its default dark theme) from `compose.cloud.yml` and `edge/compose.edge.yml`, Docker Engine 29.1.3 with Docker Compose 2.40.3. **The author has no VPS, domain, Cloudflare, phone, or router that can be unplugged, so everything is simulated on that machine:** the "internet" = a Docker network; the "VPS" = a container holding one address on that network; Let's Encrypt = **Pebble 2.10.1**; the DNS = **pebble-challtestsrv 2.10.1**; the lab domain name `iot.example.test` (the text writes `iot.yourname.my.id`; the temporary friend account's email `friend@example.test` shows on the Log in screen); Chrome accepts the Pebble certificates only in the lab profile (`--host-resolver-rules` + the Pebble root's fingerprint), without touching the system's certificates; "unplugging the home internet" = taking the simulated Pi gateway's broker container off that network; the Cloudflare tunnel on the free path was played by a stand-in container (no Cloudflare account; `cloudflared` without a token refuses to start). **Headless Chrome only captures the page content: the address bar, the padlock, the app-install dialog, and DevTools never show** (and are not imitated). The data senders are mock programs: the simulator `f00d00000001` and the **mock Garden** `f00d000000b2` (`tools/`) plus the practice history of earlier modules, not a real Node 1/Node 2; Telegram = a mock Bot API server with a lab-only overlay (no screenshot of the Telegram app). The accounts in the screenshots are lab test accounts (no password shows). The numbers and times are examples from the simulated lab (30 Oct 2026, WIB), not VPS, Let's Encrypt, or real home-network numbers; the composites show the English lab's own runs (for example the two 10-minute unplugs at 17:53–18:04 and 18:08–18:19 WIB), while the diagrams keep the Indonesian story numbers.
